### 成果物

`safe-store.js`（`window.SafeStore`）が3層の防御を担う。**本番へ書き込む関数は存在しない。**

| 層 | 実装 | 効果 |
|---|---|---|
| 第1層 | `guardCheck()` | 全消失・急減（既定60%未満）・読込前保存をブロック |
| 第2層 | `app/notebook_v2_snap` | 直近5世代を保持。起動時に1世代積む |
| 第3層 | `localStorage['awsStudyDeckV2Mirror']` | クラウド障害時の控え |

### v2ブランチのファイル構成

```
index-v2.html   ← 元 index.html。インラインFirebaseモジュールをブート処理に差し替え
app-v2.js       ← 元 app.js のコピー（段階3-1時点で中身は無変更）
data-v2.js      ← 元 data.js のコピー（段階3-1時点で中身は無変更）
safe-store.js   ← 新規。保存レイヤー
store.js        ← 共有。FIREBASE_CONFIG の供給元
```

設置済み。`michael-803.github.io/aws/index-v2.html` で動作確認済み。

### 調整ポイント

`safe-store.js` 冒頭の定数。

- `SYNC_MODE` … `'refresh'`（既定）/ `'keep'`（保存機能をテストするとき）
- `GUARD.dropRatio` … 既定 `0.6`
- `MAX_GENS` … 既定 5

### コンソール操作

```js

await SafeStore.listSnapshots() // 控えの一覧
await SafeStore.restore(0)      // 0番目の控えから復元（自動リロード）
```

## 4. 段階3の確定仕様

### 4-1. 安定ID化【最重要・最初にやる】

**問題**：組み込みカードのIDが `b::カテゴリ::配列index`、過去問が `QQ.indexOf(q)`、
模試が `examId:問題番号`。**どれも配列の並び順に依存**しており、1件でも挿入・削除・
並べ替えをすると、過去の学習履歴が別の項目にズレて付く。

**対応**：全413項目に明示IDを付与し、既存履歴を移行する。

| 対象 | 新ID | 現キー | 移行方法 |
|---|---|---|---|
| 組み込みカード151枚 | `B0001`〜`B0151` | `b::カテゴリ::index` | 現 `data.js` の並び順から機械生成（生成可能を検証済み） |
| 独自カード | `C<timestamp>`（現状維持） | `c::<timestamp>` | 変更不要。**既に安定** |
| 過去問67問 | `Q001`〜`Q067` | `String(index)` | 現 `data.js` の並び順から機械生成 |
| 模試195問 | `M1-001`〜`M3-065` | `examId:index` | 現 `mock-exam.html` の並び順から機械生成 |

**カテゴリにも安定IDを振る**（`cat_compute` 等）。現状は日本語文字列がキーなので、
将来カテゴリ名を変えると進捗・独自カードの所属が壊れる。`data.js` を触るこの機会に潰す。

### 4-2. 保存レイヤー統合

index系が `app/notebook`、模試・道場が `app/storage` に分裂し、Firebase SDKも二重初期化。
**全ページを `SafeStore` に一本化**し、1ドキュメントに統合する。

同時に修正するバグ：

### 4-3. 単語帳の機能追加

**タブ（カテゴリ）ごとの進捗保持**
現状 `fcTabState` は `datasetKey`（= `'aws'`）単位で1つだけ。これをカテゴリ単位に分割する。

```
fcProgress: {
  '<カテゴリID or __all__ or __weak__>': {
    orderIds: [], pos: 0, shuffled: false, reverse: false, answeredIds: []
  }
}
```

容量試算：全カテゴリ分で約8KB。Firestoreの1MiB上限に対して十分余裕あり。負荷の心配は不要。

**シャッフルのトグル化**

- 押す（OFF→ON）… 現在のデッキをランダム並べ替え、先頭へ
- もう一度押す（ON→OFF）… **シャッフル中に答えていないカードだけ**を、本来の並び順で出題
- さらに押す … 残り（未回答分）を再びランダム
- **一周して全部答えたら `answeredIds` を自動リセットし、全カードに戻る**（確定仕様）
- 「答えた」の定義 = 「わかる」「わからない」のどちらかを押した

**全カードに編集・削除ボタン**
組み込みカードは `data.js`（コード）にあるためアプリから消せない。よって：

- 編集 … 上書きレイヤー `cardEdits: { 'B0001': {term, def, img} }` を重ねる
- 削除 … `hiddenCards: ['B0001']` に入れて表示から除外する**論理削除**
- **「非表示にしたカード」一覧画面を用意し、いつでも復活できるようにする**

**改行対応**
`white-space: pre-wrap` を当てる。textareaの改行がそのまま表示される。
HTMLを解釈しないので安全（`escHtml` はそのまま維持）。

**画像対応**
Firebase Storageは**使用不可**。2026年2月3日以降、バケットの作成・維持にBlazeプラン
（クレジットカード登録）が必須。Sparkのままだと402/403エラーになる。
Firestoreへの直接埋め込みも1MiB上限のため不可。

→ **Cloudinaryを使う**（さくらさんの既存アカウント `dnbbwfwoi`／BreakinSetBuilderで使用実績あり）。
**アプリから直接アップロードする方式**（確定）。Firestoreには `secure_url` 文字列のみ保存するので、
カードが増えても容量は問題にならない。必要な設定は第6節を参照。

### 4-8b. 選択肢シャッフル機能【完了】

択一式・複数選択式の全問題で、選択肢の表示順を固定にしておくと「位置で答えを覚えてしまう」
という学習上の弱点が生まれる。これを避けるため、以下の仕様で選択肢シャッフルを実装した。

**対象**：複数選択問題（`MULTI_Q`）／過去問（`QQ`）／シナリオ問題（`SCENARIO_Q`）の3つ全て。

**仕様**：
- 設問を開く（描画する）たびに、選択肢の表示順をFisher-Yatesでシャッフルする
- 一度表示された後、その設問に解答するまでは表示順を固定する（再描画は次の設問に進むときにしか
  発生しない設計のため、自然と満たされる）
- **正誤判定・DOM要素ID・選択状態・誤答プールへの記録は、常に元データの配列インデックス
  （選択肢の内容そのものと1対1で対応する安定した識別子）を基準に行う。表示位置には一切依存しない。**
  シャッフルは「見た目の並び替え」のみで、内部ロジックは表示順シャッフル導入前とまったく同じ
  インデックスベースのまま変更していない。
- 組み込み問題の編集・削除ボタン（複数選択問題のみ実装）は設問ID単位で動作するため、選択肢の
  シャッフルとは無関係に常に正しい設問を指す。編集フォームも元データ（未シャッフルの順序）から
  直接読み込むため、シャッフル表示中に編集を開いても正しい選択肢に正しく反映される
  （実データで実際にテスト済み）。

**今後の指針**：新しく選択式の問題形式（択一・複数選択問わず）を追加する場合は、
**最初からこの仕様（開くたびにシャッフル・解答まで固定・判定は内容/IDベース）を組み込むこと。**
後から追加するとレンダリング部分の手戻りが発生するため、最初の設計段階で織り込んでおくのが望ましい。

### 14-2. 【重要】CLFに無かった新しい出題形式が2つある

公式ガイドの「Question types」に、CLF-C02には無かった形式が明記されている。
**既存エンジンは択一式・複数選択式にしか対応していないため、2つの出題エンジンを新規実装する必要がある。**

| 形式 | 仕様（公式ガイドの記述） | 既存対応 |
|---|---|---|
| 択一式（Multiple choice） | 正解1つ＋誤答3つ | ✅ `QQ` エンジン |
| 複数選択式（Multiple response） | **5つ以上の選択肢から2つ以上**を選ぶ。全部合っていないと得点にならない | ✅ `MULTI_Q` エンジン（※選択肢数を5以上に増やす必要あり） |
| **順序問題（Ordering）** | **3〜5個の選択肢を正しい順に並べる。**順序も含めて全て正しくないと得点にならない | ❌ **新規** |
| **マッチング問題（Matching）** | **3〜7個の設問と選択肢を対応付ける。**全ペア正解で初めて得点 | ❌ **新規** |

**新エンジンのUI方針（スマホ優先）**

ドラッグ＆ドロップはスマホで操作性が悪いため使わない。

- **順序問題**：選択肢をタップした順に 1→2→3… と番号が振られる方式。「やり直し」ボタンで解除。
  データ形式は `{id:'O001', c:カテゴリID, q:設問, o:[選択肢...], a:[正解の並び順のindex配列], e:解説}`
- **マッチング問題**：左に設問、右に選択肢。設問をタップ→対応する選択肢をタップ、で線がつながる方式。
  データ形式は `{id:'MT001', c:カテゴリID, q:設問, l:[左...], r:[右...], a:{左index:右index}, e:解説}`
- **どちらも 4-8b節の指針どおり、選択肢シャッフルを最初から組み込む。**
  順序問題は表示順をシャッフルし、正誤判定は元データのindexで行う。

### 14-3. 単語帳：カテゴリの複数選択【さくらさん要望・2026-08-15】

現状の単語帳はカテゴリを1つしか選べない（`currentKey` が単一値）。
これを**任意の複数カテゴリを組み合わせて出題できる**ようにする。

**キーの設計（既存データとの互換を保つ）**

`fcProgress` のキーを以下のとおり導出する。**1つだけ選んだ場合は現行キーとまったく同じになる**ため、
既存の学習進捗はそのまま引き継がれる。

| 選択状態 | `fcProgress` のキー | 互換性 |
|---|---|---|
| 0件（＝全カテゴリ） | `_all_` | 現行と同一 |
| 1件 | そのカテゴリID（例 `cat_bedrock`） | **現行と同一** |
| 2件以上 | `m:` ＋ ソート済みIDを `+` 連結（例 `m:cat_bedrock+cat_genai`） | 新規 |
| 苦手のみ | `_weak_` | 現行と同一（今回は排他のまま。組み合わせ対応は将来課題） |

IDをソートしてから連結するので、選ぶ順番が違っても同じキーになる（＝進捗が分裂しない）。

**肥大化対策**：9カテゴリなら組み合わせは最大511通り。全部保存すると `fcProgress` が膨らむため、
**`m:` で始まるキーは直近10件のLRUで保持し、超えた分は古いものから削除する。**
単一カテゴリ・`_all_`・`_weak_` は削除対象にしない。

**UI方針**：**チップは常にチェックボックスとして振る舞う**（モード切り替えは無い）。

- カテゴリチップをタップするたびに、そのカテゴリを出題対象に入れる／外す。組み合わせは自由で個数制限なし
- 「全カテゴリ」チップは選択をすべて解除するボタンとして働く
- Firestoreの予約語（`__x__` 形式）を避けるため、接頭辞は単一アンダースコアを維持する（4-1節の既知の罠）

> **一度モード切り替え式（「複数選択」トグルを押してからチップを選ぶ）で作ったが、廃止した。**
> トグルを押す必要があることに気づけず、チップを2つタップしても切り替わるだけなので
> 「複数選択が実装されていない」ように見えてしまったため。**先に何かを押させる設計にしない。**

**スマホでの折りたたみ**：カテゴリが9つあるとチップが6段・233pxを占め、カードと
「わかる／わからない」が画面外に押し出される。`@media(max-width:680px)` では
`📂 カテゴリ ＜選択中の内容＞ ▼` という見出しに畳み、タップで開く形にする（PCでは常に展開）。
畳んだ状態でも見出しに選択中のカテゴリ名と枚数が出るので、何を出題しているかは分かる。

**この機能は `_engine/engine.js` 側に実装する**ので、AIF以降の全資格で使える。
CLF（`/aws/app.js`）は据え置き方針のため反映しない。CLFにも欲しい場合は別途相談。
